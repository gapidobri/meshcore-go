# meshcore-go

A TinyGo reimplementation of the [MeshCore](https://github.com/meshcore-dev/meshcore)
LoRa mesh library, wire-compatible with the C++ implementation.

```
import meshcore "github.com/gapidobri/meshcore-go"
```

## Status

Milestone 1 covers the core library and is byte-exact with upstream
`81dbae5`:

| C++                                 | Go                                                  |
| ----------------------------------- | --------------------------------------------------- |
| `Packet`                            | `Packet` (`Encode`/`Decode`, `CalculateHash`)       |
| `Identity`, `LocalIdentity`         | `Identity`, `LocalIdentity`                         |
| `Utils` (sha256, AES, MAC, hex)     | `SHA256`, `Encrypt`, `EncryptThenMAC`, `ToHex`, ... |
| `Dispatcher` + `Mesh`               | `Mesh` (one type)                                   |
| virtual hooks on `Dispatcher/Mesh`  | `Handler` interface + embeddable `BaseHandler`      |
| `StaticPoolPacketManager`           | `StaticPoolPacketManager`                           |
| `SimpleMeshTables`                  | `SimpleMeshTables`                                  |
| `AdvertDataBuilder/Parser`          | `AdvertData.Encode`, `ParseAdvertData`              |
| `TxtDataHelpers`                    | `TxtType*`, `StrZCopy`, `Ftoa`, `Ftoa3`, ...        |
| `RadioLibWrapper` + `CustomSX1262`  | `sx1262.Radio` (TinyGo only)                        |

Out of scope for now: `BaseChatMesh` (contacts, channels, DMs), `RegionMap`,
transport keys, CLI, and the firmware apps (companion, repeater, room server,
sensor, KISS modem).

## Usage

```go
type node struct {
	meshcore.BaseHandler // required; supplies the C++ default behaviour
}

func (n *node) AllowPacketForward(p *meshcore.Packet) bool { return true }

func (n *node) OnAdvertRecv(p *meshcore.Packet, id *meshcore.Identity, ts uint32, app []byte) {
	ad := meshcore.ParseAdvertData(app)
	println("advert from", ad.Name())
}

m := meshcore.NewMesh(meshcore.Config{
	Radio:   radio, // e.g. sx1262.New(...)
	Millis:  meshcore.NewSystemMillis(),
	RNG:     rng,
	RTC:     rtc,
	Packets: meshcore.NewStaticPoolPacketManager(16),
	Tables:  &meshcore.SimpleMeshTables{},
	Handler: &node{},
})
m.SelfID = meshcore.NewLocalIdentity(rng)
m.Begin()
for {
	m.Loop()
}
```

Override any `Handler` method to customise behaviour. Call
`n.BaseHandler.RetransmitDelay(p)` (and so on) for the default, and
`n.Mesh()` to reach the mesh. The library assumes a single poll loop and is
not safe for concurrent use.

Identities use the C++ 64-byte expanded private-key format, so keys move
between implementations unchanged (`LocalIdentity.AppendBinary` /
`LoadLocalIdentity`).

`examples/t3s3` is a minimal forwarding node for the LilyGo T3S3 (ESP32-S3 +
SX1262):

```
tinygo flash -target esp32s3-generic ./examples/t3s3
```

`examples/rak4631` is the same node for the RAKwireless RAK4631 WisBlock core
(RAK4630 module: nRF52840 + SX1262). Double-tap reset to enter the UF2
bootloader, then:

```
tinygo flash -target rak4631 ./examples/rak4631
```

## Interop testing

`testdata/golden.json` is generated by `tools/golden/gen.sh`. The script
builds the upstream C++ sources (with rweather/Crypto and orlp/ed25519) on the
host against small Arduino shims, then emits vectors for:

- keypairs, signatures, verification, ECDH (including degenerate public
  keys) and private-key validation
- AES-ECB, encrypt-then-MAC, SHA-256
- packet decode/encode/hash
- advert encoding/parsing, relative-time and float formatting
- a 26-step, two-node mesh scenario run over a simulated radio. It covers
  every payload type, flood/direct/zero-hop/transport routing, multi-byte path
  hashes, trace, multipart ACKs, path returns, dedup and malformed input. Every
  transmitted byte and every handler event must match, including the
  RNG-driven retransmit timing.

`go test ./...` replays all of it.

## Deliberate differences from the C++

- Malformed packets that would make the C++ read past the valid data
  (truncated transport codes, short TRACE/CONTROL payloads, PATH payloads whose
  path overruns the plaintext) are rejected. Valid traffic is unaffected.
- `SendFlood` with a TRACE packet or an invalid path hash size, and
  `SendDirect` with an oversized TRACE path, return the packet to the pool
  instead of leaking it.
- `LoadLocalIdentity` returns an error for blobs that are not 64 or 96 bytes.
- `Mesh::onPathRecv` is omitted (the core never calls it). Stream-based I/O,
  `printHex` and `parseTextParts` are left to the Go standard library.
- The SX1262 adapter detects channel activity from preamble/header IRQs and
  the RSSI interference threshold. Hardware CAD (`SetCADEnabled`) is ignored.

## Allocations

The repeater hot path (receive, parse, dedup, route, transmit) does not
allocate. `TestForwardDoesNotAllocate` checks this under gc, and
`tinygo build -print-allocs` confirms it for the ESP32-S3 build. Packet hashing
and HMAC use a small internal SHA-256, because TinyGo heap-allocates
`crypto/sha256`'s digest.

Still allocating: the AES key schedule on each encrypt/decrypt (only for
packets addressed to this node or a matching channel), Ed25519 verification of
received adverts, and signing.
